# grpc-go baseline

`trevrpc-bench-grpc` is the gRPC-over-HTTP/2 baseline for the [load benchmarks](../README.md), so TrevRPC's numbers can be compared with stock grpc-go on the same machine. It is a separate Go module that does not depend on `trevrpc-go`. It generates `echopb` from the shared [`interop.proto`](../../interop/proto/interop.proto) with `protoc-gen-go` and `protoc-gen-go-grpc` (pinned as `tool` directives in `go.mod`); a test regenerates the code and fails on drift, and `go test ./echopb -update` rewrites it.

`server --cert --key [--host] [--port]` serves `trevrpc.interop.v1.Echo` with the behavior in [`interop/README.md`](../../interop/README.md) over gRPC with TLS, prints `{"grpc":<port>}` once it is accepting, and exits when stdin reaches EOF. `bench` implements the client contract: all workers share one `grpc.ClientConn`, each with one call in flight (`bidi` keeps one stream per worker open), and it prints the same JSON line with `transport: "grpc"`. `--tcp-addr` is accepted and ignored. Everything else is grpc-go's default, with no tuning. `wire_bytes_per_msg` counts the bytes of the client's TCP connection (TLS records, HTTP/2 framing included) through a counting `net.Conn`, the analogue of the UDP payload measure used for QUIC.
